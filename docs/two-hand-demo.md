# Two Shadow Hands and a procedural ukulele

Copy bimanual_scene.py and run_two_hand_demo.py into StrumOnCue/scripts. Run from the repository root. Requires the existing outputs/c-contact/scene.xml generated by find_c_contact.py and the pinned external/mjlab_hand submodule. No extra Python package is required for numeric execution or the native viewer.

## What is implemented

- Decorative double-bout wooden body, fretboard, faux soundhole/rosette, headstock, tuners, bridge, saddle, and inlays. Appearance geoms have collisions disabled. The pre-existing neck/body/string collision geometry is retained. The faux soundhole is a dark disk, not a cut-out acoustic cavity; visual body outline and collision proxy differ.
- Left Shadow Hand retains its C candidate and candidate-4 scripted finger commands.
- Right Shadow Hand holds a curled posture except for the index finger and moves on three world-axis slide joints driven by position actuators. This is a Cartesian stage, not a full robot arm. Measured index-fingertip position supplies crossing events. There is no mocap probe and no runtime qpos teleportation.
- Right-hand/string collisions are disabled as permitted by the symbolic detector design. Right-hand/neck/body and hand/hand collisions remain enabled. Collision filtering uses bitmasks.
- String order, scale length, fretting targets, and left controller commands are unchanged.

## New physical/control settings

The combined scene uses implicitfast integration at 0.002 s. Right-hand body gravity compensation is enabled. Right-hand joint position servos use kp=20, kv=1, force limits +/-10 in actuator units. The stage uses kp=8000, kv=200, force limits +/-200 N and +/-1 m joint/control ranges. A Cartesian feedback correction and 0.025 s velocity feedforward command the stage. The desired strum point is 0.7 mm above the string center, within the explicit 2 mm symbolic crossing-height tolerance. These are simulation engineering choices, not calibrated hardware specifications. They are recorded in the result summary.

The strum spans 0.30 s; expected per-string timestamps use that sweep. Returning strokes lift first. Crossings are detected from actual fingertip motion, including unexpected reverse crossings; event matching uses string/pitch/onset and unexpected upstrokes are separately counted and fail the screen. The 30 ms duplicate debounce is provisional. Frame-rate, force, and contact tolerances need broader validation before research evaluation.

## Verified locally

MuJoCo 3.1.4, 10 cycles / 80 simulated seconds: TP 160, FP 0, FN 0, mean absolute matched onset error 2.839 ms. Every cycle had clean-release fraction 1.0, hold fraction 1.0, and unwanted-contact fraction 0.0. No simulator warnings or self-contact force recorded. Reproduce on CARC 3.8.1; this development result is not a robustness estimate. The accompanying local summary predates a label clarification from forearm_fixed to fretting_mount_fixed; the right stage moves physically.

Numeric compilation and rollout were checked. Native visual appearance and video encoding still require inspection in a graphics-enabled session. Native viewer: mjpython scripts/run_two_hand_demo.py --cycles 2 --view --output outputs/two-hand-view-01.

Optional video: add --video on an allocated GPU with MUJOCO_GL=egl. Requires imageio and an FFmpeg backend. Do not render on a login node.

This is not RL, generalization, acoustic simulation, or a full-arm bimanual robot. It is the scripted two-hand baseline used to validate the task pipeline.
